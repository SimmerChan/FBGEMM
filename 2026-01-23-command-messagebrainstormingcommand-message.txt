  第二章：核心组件设计

  2.1 统一分发器 (Dispatcher)

  分发器是整个架构的核心，负责根据张量设备类型路由到对应后端实现。设计要点：

  文件位置: fbgemm_gpu/src/npu/dispatch/dispatcher.h

  分发器提供统一的算子入口，使用前向声明避免循环依赖。通过inline函数保证零额外开
  销，编译器会优化掉函数调用。分发逻辑使用简单的if-else链，根据tensor.device().t
  ype()判断：

  c10::DeviceType device_type = tensor.device().type();
  if (device_type == c10::kPrivateUse1) {  // NPU
      return npu::op_npu(tensor);
  } else if (device_type == c10::kCUDA) {
      return cuda::op_cuda(tensor);
  } else {
      return cpu::op_cpu(tensor);
  }

  为避免代码重复，设计宏系统自动生成分发器。支持两种扩展模式：
  - 单算子添加: 手动注册新算子的分发函数

    // 映射到AscendC的数据类型

    } else if constexpr (std::is_same_v<index_t, int64_t>) {
      return call_ascendc_op<int64_t>(permute);

  5.3 为什么不需要批量注册宏

  理由：
  1. 保持一致性：CUDA没有批量宏，NPU也不应该引入
  2. 简单优先：YAGNI原则，目前不需要那么复杂的抽象
  3. 减少学习成本：昇腾团队只需理解现有的CUDA注册模式
  4. 灵活性：逐个注册更灵活，特殊算子可以单独处理

  如果将来需要批量注册，可以在不破坏现有代码的前提下渐进式添加：
  // 可选的批量宏（未来需要时再添加）
  #define REGISTER_NPU_SPARSE_OPS(m) \
    m.impl("invert_permute", &dispatch::invert_permute); \
    m.impl("permute_1d", &dispatch::permute_1d); \
    m.impl("permute_2d", &dispatch::permute_2d);

  TORCH_LIBRARY_IMPL(fbgemm, CatchAll, m) {
    REGISTER_NPU_SPARSE_OPS(m)
  }

  但目前不建议引入，保持最简单的逐个注册方式。

  5.4 注册优先级说明

  PyTorch的调度优先级：
  1. 具体设备类型 (CUDA/CPU)  ← 优先级高
  2. CatchAll                   ← 优先级低，但可以覆盖所有情况

  通过CatchAll注册分发器后：
  - CUDA张量：分发器检测到device.type() == CUDA，调用cuda::op_cuda()
  - NPU张量：分发器检测到device.type() == PrivateUse1，调用npu::op_npu()
  - CPU张量：分发器检测到device.type() == CPU，调用cpu::op_cpu()

  这样无需修改CUDA现有注册代码，完全解耦。

        permute.numel());

  5.3 为什么不需要批量注册宏

  理由：
  1. 保持一致性：CUDA没有批量宏，NPU也不应该引入
  2. 简单优先：YAGNI原则，目前不需要那么复杂的抽象
  3. 减少学习成本：昇腾团队只需理解现有的CUDA注册模式
  4. 灵活性：逐个注册更灵活，特殊算子可以单独处理

  如果将来需要批量注册，可以在不破坏现有代码的前提下渐进式添加：
  // 可选的批量宏（未来需要时再添加）
  #define REGISTER_NPU_SPARSE_OPS(m) \
    m.impl("invert_permute", &dispatch::invert_permute); \
    m.impl("permute_1d", &dispatch::permute_1d); \
    m.impl("permute_2d", &dispatch::permute_2d);

  TORCH_LIBRARY_IMPL(fbgemm, CatchAll, m) {
    REGISTER_NPU_SPARSE_OPS(m)
  }

  但目前不建议引入，保持最简单的逐个注册方式。

  5.4 注册优先级说明

  PyTorch的调度优先级：
  1. 具体设备类型 (CUDA/CPU)  ← 优先级高
  2. CatchAll                   ← 优先级低，但可以覆盖所有情况

  通过CatchAll注册分发器后：
  - CUDA张量：分发器检测到device.type() == CUDA，调用cuda::op_cuda()
  - NPU张量：分发器检测到device.type() == PrivateUse1，调用npu::op_npu()
  - CPU张量：分发器检测到device.type() == CPU，调用cpu::op_cpu()

  这样无需修改CUDA现有注册代码，完全解耦。

  torch.cuda.synchronize()
      elapsed = time.time() - start
